## Pages (site/)

Les 5 premières existent déjà en version « échantillon » (`carte_reseau.html`, `frise_avions.html`) ou non : elles sont à refaire à partir de `enriched.jsonl`.

- [x] **carte-reseau** — Carte animée du réseau : lignes ouvertes/fermées dans le temps sur un planisphère (`routes` des enregistrements ; remplace `carte_template.html`).
- [x] **frise-avions** — Frise des avions : tous les appareils (modèle, famille) avec première et dernière mention, y compris ceux que l'ancienne liste regex manquait (Comet…).
- [x] **personnages-lieux** — Personnages et lieux : index des personnes (rôle, période, textes) et des lieux (carte + liste, noms historiques).
- [x] **greves-records** — Grèves et accidents face aux records et inaugurations : deux courbes/frises par année (catégories `greve_social`, `accident_incident` contre `record`, `premier_vol`, `ouverture_ligne`), ton, victimes.
- [x] **ce-jour-la** — « Ce jour-là chez Air France » : choisit le jour (par défaut aujourd'hui, sélecteur de date) et affiche les événements de ce jour-mois, classés par intérêt.
- [x] **monde-retrecit** — Le monde rétrécit : durées de trajet (`routes.duration_hours`) par destination au fil des décennies.
- [x] **genealogie** — Généalogie des compagnies : arbre/chronologie des compagnies (`companies`, catégories `entreprise_capital`) : fusions, créations, filiales.
- [x] **vie-avion** — La vie d'un avion : parcours d'un appareil par immatriculation (`aircraft.registration`, `event`) : commande → livraison → incident → retrait.
- [x] **villes-renommees** — Villes renommées : lieux dont `historical_name` ≠ `name` (Saïgon → Hô Chi Minh-Ville), avec la carte et la date. Attention : `historical_name` est le nom employé dans le texte, donc bruité (aéroports « Orly »/« Paris-CDG » → Paris, variantes d'orthographe « Fort de France », « Francfort »). Ne garder que les vrais changements de nom : écarter les noms identiques après normalisation (accents, tirets, casse), les aéroports et les simples abréviations ; vérifier à la main les ~50 paires les plus fréquentes (Tananarive, Saïgon, Fort-Lamy, Bône…).
- [x] **graphe-personnes** — Le graphe des personnes : réseau des personnes co-citées, taille = nombre de textes, couleur = `kind`.
- [x] **prix-billets** — Prix des billets : `figures` de type tarif, en francs puis en euros, par ligne et par année.
- [x] **chiffres** — Air France en chiffres : passagers, flotte, effectifs, chiffre d'affaires, résultats (`figures` de la compagnie) en séries temporelles.
- [x] **barometre-crises** — Baromètre des crises : intensité par année (catégories `guerre_crise`, `greve_social`, `securite_surete`, tonalité négative), avec les événements marquants.
- [x] **devine-annee** — Devine l'année : quiz à partir d'un texte (intérêt ≥ 4, sans date dans le texte), score selon l'écart.
- [x] **demande-musee** — Demande au musée : recherche plein texte côté navigateur (index des titres/résumés/personnes/lieux, tolérant aux accents) ; pas d'appel LLM ni de clé dans la page.
- [x] **accueil** — `site/index.html` : généré par `build_site.py` à partir des `META` ; vérifier qu'il liste les 15 pages, qu'aucun lien n'est mort, et ajouter une capture ou une phrase d'accroche par page.
- [x] **quiz** — Le Grand Quiz : 116 questions (3 niveaux), parties de 5 questions en 5 modes (carte cliquable, frise, estimation, chronologie, devinette), jusqu'à 5 000 points par question selon précision × rapidité, classement local (export/import).
- [x] **design-musee** — Habillage « musée » : l'accueil est le plan d'une aérogare (jetées A–D, hall, Concorde à quai), chaque page est une salle (signalétique, cartel, vitrine, portes vers les salles voisines, plan). Pages et design découplés : `pages/*.py` ne produisent que leur contenu (`Exhibit`), `design/*.py` l'habillage (`--design sobre` pour l'ancien).

## Conventions

- Une page = un module `pages/<slug>.py` avec `META = {"slug", "title", "description", "order"}` et `build(data) -> Exhibit` (contenu seul, données incluses, via `page_shell`). Voir `pages/common.py` (`Data`, `embed`, `page_shell`) ; l'habillage vient de `design/` (voir `AGENTS.md`).
- Construction : `.venv/bin/python build_site.py <slug>` (une page) ou sans argument (tout + accueil). Sortie dans `site/`.
- Pages autonomes : données inlinées, seule dépendance externe autorisée = D3 v7 via jsdelivr. Français, accents corrects. Lisible en clair et en sombre. Lire le skill `dataviz` avant d'écrire un graphique.
- Les données viennent de `enriched.jsonl` ; le texte complet d'origine est dans `ephemerides.json` (clé `id` = index). Ne pas inventer de données : une page qui manque de matière le dit.
- Vérifier chaque page avant de cocher : elle se construit sans erreur, le JS n'a pas d'erreur (relire le code, tester la logique sur les vraies données avec un script), le fichier existe dans `site/`.
- Ne pas modifier `enriched.jsonl`, ne pas relancer ni arrêter `enrich.py`, ne pas appeler d'API payante.
